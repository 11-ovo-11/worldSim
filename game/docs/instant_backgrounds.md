# 即时场景背景

在对话区的“设置”中开启“即时生成场景背景”并确认，开关会成为之后运行的默认值。
开启后，每次有效的 NPC 回复或行动回复都会异步生成环境背景；切换开关不会改变文本提示词和记忆逻辑。
关闭后停止新的图片请求并保留最后一张背景。

## 本轮文本与单画面选择

- 行动栏和对话栏都会把实际发送的本轮输入与对应 AI 回复绑定，开场则只使用开场回复；不会误用另一输入栏的旧内容。
- 本轮输入决定主要事件、地点和核心行为，AI 回复补充兼容的动作、构图、表情、道具与光照。两者冲突时优先输入。
- 对话里的询问、假设或愿望不会直接当成已发生的动作；“继续”根据回复承接当前事件。
- 多地点、连续动作或多个效果只选与输入最相关的一处、一个瞬间，不生成拼图、分镜或多张候选。输入无明确指向时选择回复的主要场景。
- 游戏地点、时间天气只是兜底资料，正文明确指定的场景优先。立绘绑定外观，人物姿势随实际事件改变。
- 保留本轮输入，AI回复最多6000字符，覆盖现有最大输出设置，不再只保留回复开头和结尾。Codex在同一个生图任务内先精炼为约120至220字的画面提示词，不另调文本API。
- 每轮输入与回复保存在独立快照中；排队期间的新输入不会改写已有请求。设置中开启生图时，使用最近回复自身绑定的输入。
- 图片请求不携带完整历史、世界提示词或后台工具数据。总资料超过12000字符会明确报错，避免后端静默截断重要动作。

## Codex 命令行（默认）

默认通道为 `WORLD_SIM_BACKGROUND_PROVIDER=codex_cli`，不要求另配 `OPENAI_API_KEY`。
优先使用已安装的Codex桌面原生命令行，其次才使用PATH中的npm命令行。本机桌面命令行为0.166.0-alpha.5.1，旧npm命令行为0.154.0。
游戏把短场景资料交给独立的 `codex exec` 任务，读取生成的 PNG 后替换背景；不会向当前桌面聊天注入消息。
命令行需安装、登录并具有内置生图权限；使用限制及计费取决于 Codex 的实际登录/账户配置，不能视为无限免费。

```powershell
codex --version
codex login
codex features list
```

`GET /instant_image_status` 仅检查本机是否找到 CLI，不会主动生成图片，也不代表账户权限或额度验证成功。
命令行任务位于独立临时目录，使用 `workspace-write` 沙箱，场景文本先写入任务自己的UTF-8临时文件，再将该文件作为标准输入，不拼接成shell命令。这样避免Windows管道写满时阻塞监控循环；文件随任务目录清理。
子进程不会继承桌面当前聊天的工具管道及会话标识；仅在本次生图调用中关闭无关MCP、插件、记忆、浏览和多代理，保留现有登录、模型、提供商、代理及权限配置。不会修改全局config.toml。
任务不得读取原始存档、项目配置或密钥；不允许在内置工具不可用时静默改用付费图片 API。

### 人物立绘绑定

- 本轮输入点名的人物优先，其次是本轮对话 NPC，再查找本轮叙事中明确提到的已有人物；最多附带三张立绘。
- 从原始缓存/本地 NPC 图片中读取图像，通过 CLI `--image` 作为实际图片输入，并附带人物名与图片对应表。
- 要求内置生图工具继续使用这些图像参考，保持五官、发型、发色、服饰和体型，不能仅凭文字重新设计人物。
- 缺少立绘的人物不自行补画；参考图无法使用时报告失败，不退化为无参考重画。
- 参考副本最长边1024像素以控制传输与视觉输入开销，原立绘文件不修改；立绘内容更换时生成缓存自动失效。
- 这是模型参考约束，不能保证所有角度和每次生成都达到像素级身份一致。仅支持非露骨场景与完整着装人物。

## 公开图片 API（仅手动选择的备用通道）

仅在环境变量中明确设置 `WORLD_SIM_BACKGROUND_PROVIDER=openai` 时才调用公开 Images API。
该通道需要 `OPENAI_API_KEY` 或优先级更高的 `WORLD_SIM_OPENAI_IMAGE_API_KEY`，独立于 DeepSeek/旧 `image_key.py`。
默认模型 `gpt-image-2.5-flare`，可通过 `WORLD_SIM_OPENAI_IMAGE_MODEL` 更改。
该备用通道目前只支持无人物参考的背景生成，收到立绘参考会报错，不会忽略立绘。
网络继承环境/系统代理；`NO_PROXY` 可添加 `localhost,127.0.0.1` 排除本地桥接。

## 速度与显示

- Codex 默认仅生成一张图，请求低质量1024x640或工具支持的最小横向尺寸、简洁背景；实际输出分辨率由内置工具决定。
- 生图调度任务单独使用低推理开销，不改变文字对话模型设置。只读取本轮CLI会话专属的工具原图，写完即可返回，无需等模型再复制图片或输出结语。
- 同时识别旧命令行的`call_*.png`与桌面原生命令行的`exec-*.png`，只读取本次会话目录中已写完的PNG。
- 不要求模型复制图片；原图由父进程读取，以减少额外工具调用与模型往返。
- 只发送本轮输入、对应回复、短场景兜底与相关立绘，不发送完整对话历史和世界观限制提示词；生图工具收到的是精炼后的单画面提示词。
- 相同请求在桥接内缓存5分钟，最多8张；缓存键包含立绘内容。不做自动生图重试。
- 图片请求使用独立的 HTTPRequest，不占用文字请求或输入锁。忙时最多保留一个最新待处理请求。同一地点已完成的画面先显示，再处理最新输入，避免持续对话导致所有结果都被丢弃；已应用的更新版本、切换地点和读档后的画面不会被旧响应覆盖。
- 10秒无法保证，本机首次普通背景测试也花费数十秒。收到完整 PNG 后即返回并结束本轮命令行任务，不继续等待可能卡住的最终文字或遥测。只有 PNG 签名和末尾 IEND 块齐全才接受，不返回尚未写完的文件。
- Codex 任务最长等待180秒，前端195秒；尚无完整图片时超时结束本项目启动的任务，背景不变。
- 保留生成图原始分辨率，仅在显示时缩放，不把图片永久缩成界面槽位大小。

## 调试与额度

- 右侧顶部提供“日志 / 调试”按钮，默认日志。调试信息与故事日志、对话历史互相独立，不送入模型记忆，不写入存档。
- 调试文本可以拖选、Ctrl+C复制。显示文本请求与响应、生图请求编号、资料大小、立绘数量、排队、进程启动、模型连接、场景提炼、等待、取图、错误、保存位置与耗时；隐藏模型内部推理内容和凭据。
- 前端使用独立请求每2秒读取 `/instant_image_debug`，等待期间每10秒记录前端耗时，后端每15秒报告等待阶段。不会为诊断重新生图。
- 调试记录最多保留200条，后端进度环最多300条，使用游标增量读取。后端重启会自动重新同步。
- 顶部用量显示本次生成张数、缓存命中以及工具实际返回的文字token。提前取图时CLI可能还没有输出用量，明确显示“工具未返回”；缓存取图不会记作新生成。
- CLI返回的input_tokens是本轮多次模型调用的累计量，包含系统与工具上下文以及重复传入的数据，不能将它理解为游戏发送的画面资料本身有这么多token。
- 拒绝或失败后仍显示工具实际返回的文字token；没有返回的生成张数和扣费标记为未知，不记成成功生成或免费。
- 通过Codex app-server只读 `account/rateLimits/read` 查询账户额度窗口，显示已用和剩余百分比；异步查询、每分钟最多一次、最长12秒，不拖慢图片请求。
- 账户窗口是共享额度，不能用一次前后差值认定单张图片扣费；CLI没有返回的准确单图金额不会估算为免费或固定价格。公开Images API通道的余额也不能从Codex账户额度推断。
- 本次实际单图测速89.8秒，不能保证后续都比102.7秒快，更不能保证10秒。实际图片生成阶段仍占主要等待时间。

额度协议：[官方Codex app-server文档](https://learn.chatgpt.com/docs/app-server)。

## 保存与读档

每张成功背景先自动保存为 `game/picture/session/scenes/<地点>.png`，并替换当前地点的图片缓存。
普通存档会将它一并复制到 `game/saves/slot_1/resources/scenes/`；读档从该目录恢复。

如果当前游戏已经存档或读档，且磁盘存档没有被其他操作更换，生成完成后会自动更新那个存档中已有地点的背景资源，
不会自动重写游戏进度 JSON。新游戏、新地点首次仍需手动存档，避免覆盖另一个游戏时间线的进度。
读档或新游戏会取消尚未完成的生图请求，防止上一条时间线的响应污染当前存档。
